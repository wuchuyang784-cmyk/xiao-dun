# 小盾自主思考规划与工具调用机制

小盾不是被动等用户提问再回答的对话机器人，而是一个具备**自主心跳、动态工具规划、多轮工具循环**的智能体。下面详解整个机制的运作原理。

## 整体架构：三层闭环

```
┌─ 意识循环 (Consciousness Loop) ─────────────────────┐
│  定时器驱动，每 N 秒触发一次 onTick                    │
│  ├─ L2 TICK：自主心跳（无用户消息时主动苏醒）             │
│  └─ L1 消息：用户/外部消息到达时立即触发                  │
└──────────┬──────────────────────────────────────────┘
           ▼
┌─ runTurn（单轮思考）────────────────────────────────┐
│  ① 注入记忆（injector.js）                            │
│  ② 构建 System Prompt（prompt.js）                   │
│  ③ 工具意图识别 → 筛选本轮工具列表（tool-router.js）      │
│  ④ 调用 callLLM（进入工具循环）                        │
└──────────┬──────────────────────────────────────────┘
           ▼
┌─ callLLM 工具循环（llm.js）──────────────────────────┐
│  for round in 1..N:                                  │
│    ① LLM 产出 thinking + content 流式输出              │
│    ② 如果 LLM 返回 tool_calls → 执行工具 → 结果塞回     │
│    ③ 如果 LLM 纯文本无工具调用 → 收尾 break             │
└─────────────────────────────────────────────────────┘
```

---

## 第一层：意识循环 —— 何时思考

`src/runtime/consciousness-loop.js` 维护一个 `setTimeout` 驱动的定时器。每次 `onTick`：

1. **检查消息队列**：有任何新消息（用户、外部渠道、后台任务）→ 立即消费
2. **无消息时**：组装 `TICK` 字符串（当前时间、状态等）→ 作为"思考触发器"送给 LLM

这相当于给 Agent 装了一个**自主心跳**——不需要用户发送消息，Agent 自己定期醒来，看看需要干什么。

---

## 第二层：runTurn —— 思考准备

`src/index.js` 中的 `runTurn` 在每一轮思考前做三件事：

**① 记忆注入 (Injector)**

`src/memory/injector.js` 从 SQLite 中做双重检索：
- **FTS5 关键词搜索**：从用户消息中提取关键词，匹配相关记忆
- **时间窗口召回**：识别"昨天/前天/今天"等时间词，拉取对应时段记忆
- 同时注入：最近对话窗口、活跃任务、动作日志、自我感知状态等

**② System Prompt 构建**

`src/prompt.js` 将以下内容拼成完整 prompt：
- 稳定硬底板（agent 名称 / persona / 存在感描述）→ **保留 DeepSeek prefix cache 命中**
- 每轮动态块：当前时间、活跃记忆、安全约束、工具使用规则、已安装工具说明

**③ 工具注入（最关键的一步）**

`src/memory/tool-router.js` + `src/capabilities/capability-registry.js`：

- **CORE 工具永远注入**：`send_message`、`recall_memory`、`find_tool`、`ui_set`、`voice_retire`
- **按意图分组注入**：根据用户消息命中哪些 triggers（关键词正则），注入对应领域工具

```
用户说"这个聊天记录是不是诈骗"
  → FRAUD_RAG_KEYWORD_RE 命中
  → 注入 fraud_rule_screen, search_fraud_cases, check_link 等反诈工具
```

- **并非全部约 40 个工具全量注入**，只注入本轮很可能需要的子集，节省约 6-9K token

**④ find_tool 动态工具发现**

如果 LLM 发现本轮注入的工具不够用（比如用户提到了"热点新闻"但热点工具没被关键词命中注入），它可以主动调用 `find_tool`：

- `find_tool("热点 热搜")` → 搜索 capability-registry 中所有能力的 triggers/label/summary → 找到 `hotspot` 能力 → 动态装载 `hotspot_mode` 工具 schema → 下轮 LLM 就能调用了
- 这实现了**"按需激活"**：不是预加载所有工具，而是 Agent 自己根据思考结果判断缺什么、主动去找

## 第三层：callLLM 工具循环 —— 自主调用

这是核心引擎，在 `src/llm.js` 中。它是一个 `for` 循环，最多跑 `TOOL_LOOP_LIMITS.maxRounds` 轮：

```
Round 1: LLM → "我需要先鉴定这个链接"
          → tool_call: check_link("https://xxx.com")
          → 结果: { risk: "high", score: 85 }

Round 2: LLM → "链接高风险，我再查一下案例库"
          → tool_call: search_fraud_cases("虚假投资平台链接")
          → 结果: [{ case_id: 123, similarity: 0.92, ... }]

Round 3: LLM → "我有足够证据了，输出结论给用户"
          → 纯文本回复 + send_message("该链接存在高风险欺诈特征...")
          → 无 tool_calls → break
```

**关键能力：**

**① 并发工具执行**

同一轮内，如果 LLM 调了多个**只读/查询类**、互不依赖的工具，runtime 会并发执行它们（不串行等待），加速整体响应。

**② nudge 机制 — 防止 LLM "忘了收尾"**

这是工程上非常精妙的部分。LLM 有时候会：

| Nudge 类型 | 触发条件 | 干预方式 |
|---|---|---|
| `finalNudge` | 调完工具就哑火，不回复用户 | 补一条系统消息："工具结果回来了，你还没回复用户" |
| `plainTextReplyNudge` | 只输出纯文本不调 `send_message` | 提醒："纯文本不投递，请包进 send_message" |
| `actionContractNudge` | 直接说"已完成"但实际没执行工具 | 强制它必须完成真实操作再宣布 |

**③ silent signal / closer dedup**

- 系统内部刷新（silent APP_SIGNAL）时，LLM 若误调 `send_message` → 直接拦截，不让它瞎回复
- 已经发过实质性回信后，再补"有需要随时叫我"这种客套尾巴 → 拦截合并，避免冗余

---

## 第四层：工具执行 — executor

`src/capabilities/executor.js` 是一个工具名→实际实现的映射分发器，反诈工具链完整串联：

```
fraud_rule_screen（规则引擎）
    → search_fraud_cases（RAG 检索）
    → check_link（链接检测）
    → analyze_fraud_image（图片分析）
    → 综合输出风险报告
```

## 完整链路示例

```
用户发来截图"这个投资群说稳赚不赔"
        │
        ▼
[意识循环] 检测到 L1 消息 → 触发的 onTick → runTurn
        │
        ▼
[注入器] FTS5 搜记忆 + 时间召回 + 对话窗口
[工具路由器] FRAUD_RAG_KEYWORD_RE 命中 → 注入反诈 + OCR 工具
[System Prompt] 小盾人设 + 反诈工作流指引
        │
        ▼
[callLLM Round 1]
  LLM 思考："截图含文字信息，先做 OCR，同时跑规则引擎"
  → tool_calls: [analyze_fraud_image("投资群截图", ocr=true), fraud_rule_screen("稳赚不赔 投资群")]
  → 并发执行，结果回来
        │
        ▼
[callLLM Round 2]
  LLM 思考："规则引擎命中刷单诱导 + 高息理财模式，OCR 发现对公账户转账，再查案例库"
  → tool_calls: [search_fraud_cases("稳赚不赔 投资群 对公账户"), check_link(截图中的链接)]
  → 并发执行
        │
        ▼
[callLLM Round 3]
  LLM 综合结论 → 纯文本 + send_message → break
        │
        ▼
  用户收到："综合研判：高风险(92分) | 命中 '虚假投资平台' × '冒充对公账户' 套路..."
```

## 设计精髓

这套机制的核心哲学是：**Agent 不被预设的 if-else 流程锁死，而是让 LLM 在每轮中自由推理、自主决定调用哪些工具、调用几次、何时收尾。** 工程侧的工作不是"告诉 Agent 怎么走"，而是提供三个保障：

1. **给足上下文**（记忆注入 + 按需工具注入 + System Prompt）
2. **兜底纠偏**（nudge 机制防止 LLM 跑偏或遗忘）
3. **高效执行**（并发工具调用 + 动态 find_tool 按需激活）
